## How to Customize

- **Colors**: Edit the CSS variables at the top of `styles.css`
- **Fonts**: Google Fonts link is in the `<head>` of `index.html`; font names are in `:root` in `styles.css`
- **Numbers on cards**: Edit `data-count="â€¦"` on each `.stat-value` in `index.html`
- **Calendar events**: Edit the `OVERVIEW_EVENTS` / `AVAIL_EVENTS` objects at the top of the calendar section in `script.js`
- **Availability rows/units**: Edit the list items inside the cards in `availability.html` (the "days" number on each row is used by the filter tabs)
- **Listing cards**: Edit the `<article class="list-card">` blocks in `listings.html`. Each card's `data-*` attributes (category, stage, status, id, name, location, price, updated, complete, tasks, health) power the search/sort/filter â€” keep them accurate. The star rating is computed from `data-health` automatically. The Table view is built from these same cards at run time (see `script.js`), so editing a card updates both views.
- **Card thumbnails**: Each card has a placeholder image block (`.list-card__thumb`) with an image icon and "No image" label. Swap the icon/label for a real `<img>` when photos are ready. The thumb is a 16:9 band that bleeds to the card's top edge; the "No image" text lives in the `<span>` inside it.
- **Category/stage tab counts**: Edit the `<span class="tab-count">` inside the tabs in `listings.html`
- **Areas filter**: The "Areas â€” 5 mapped Â· 7 unmapped listings" dropdown above the filter bar (matching the live site). Edit the `<select id="areaSelect">` in `listings.html` to change options; each listing card's `data-location` is what the filter matches (a card with an empty `data-location` counts as "Unmapped").
- **Menu items**: Edit the `<nav>` block in `index.html`, `availability.html`, `listings.html` and `supply.html`
- **Supply numbers**: The summary cards in `supply.html` are hand-written to match the live counts â€” edit the `<b>` values and the `style="width:â€¦%"` on each `.supply-row__bar` to change a number or its mini bar. The detailed tables below are plain `<table>` markup with the same data.
- **Client Inbox rows**: Edit the `<tr class="inbox-row">` blocks in `client-inbox.html`. Each row's `data-journey`, `data-interest`, `data-objective`, `data-agent`, `data-priority`, `data-attention` and `data-query` (the search text) attributes power the filters and summary cards â€” keep them accurate. To change a client's name or phone, edit the `.inbox-name` / `.inbox-phone` text. To add filter options, add `<option>` entries to the matching `<select>` in the filter bar and use the exact same value on the rows.
- **Shortlists data**: The 50 available listings and the 13 shortlist items are the `AVAILABLE` and `shortlists` arrays at the top of the `page === 'shortlist'` block in `script.js`. Each listing is `{ name, area, price }` (price in IDR, monthly). The shortlist items can also carry `fav: true` to show the heart. The static side cards (Favourites, Client link, Rename, Client engagement, Archive) are plain markup in `shortlist.html`.
- **Profile page**: Everything on `profile.html` is plain markup â€” the opportunity strip, action buttons, Timeline, Recommended, Offers, Contracts, Viewings and the side cards. Edit the text directly in the file to change a client's details. The style classes are the `pf-*` rules in the "Opportunity profile" section of `styles.css`.
- **Login password**: Edit the `pass.value !== '12345678'` check in the login section of `script.js`
- **Links**: Currently `#` placeholders â€” update `href` attributes when wiring to real pages
